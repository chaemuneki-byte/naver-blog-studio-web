# 블로그 스튜디오 · Web

**웹앱: https://chaemuneki-byte.github.io/naver-blog-studio-web/**

키워드와 글자 수를 입력하면 한국어 제목과 본문을 생성하고, 네이버 편집기에 순차 입력한 뒤 발행하는 웹앱입니다. Windows 실행 파일이나 Python 설치 없이 Chrome/Edge에서 사용합니다.

## 사용하기

1. 웹앱의 **연결 설정**에 OpenAI API 키를 입력합니다. API 이용료는 별도입니다.
2. 글 생성만 사용하려면 바로 키워드와 분량을 입력하면 됩니다.
3. 네이버 자동 입력/발행을 사용하려면 웹앱에서 **연결 확장 다운로드**를 눌러 ZIP을 압축 해제합니다.
4. `chrome://extensions` 또는 `edge://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**로 `manifest.json`이 있는 폴더를 선택합니다. 웹앱을 새로고침합니다.
5. 본인 블로그 ID를 설정하고 **네이버 편집기 열기**로 로그인합니다.
6. 키워드와 목표 글자 수를 입력해 글을 만듭니다. **생성 후 자동 발행**을 켜면 생성부터 발행까지 이어집니다.

## 왜 연결 확장이 필요한가요?

GitHub Pages는 정적 웹 호스팅입니다. 일반 웹페이지는 브라우저의 동일 출처 보안 정책 때문에 다른 도메인의 로그인된 네이버 편집기를 직접 제어할 수 없습니다. 웹앱은 생성/원고 편집을 담당하고, 사용자의 Chrome/Edge에 설치한 연결 확장은 본인 로그인 세션에서 입력/발행을 담당합니다. 네이버 비밀번호를 별도 서버로 보내지 않습니다. 모바일 브라우저에서는 자동 발행 연결 확장을 사용할 수 없습니다.

## 포함 기능

- 키워드를 포함하는 제목 생성
- 도입 → 번호 소제목/내용 → 마무리 구성
- 각 소제목 아래 내용 **200~300자** 검사
- 전체 **500~10,000자**, 소제목·공백 포함, 제목·줄바꿈 제외, 목표 **±5%**
- 분량 오류 시 최대 4회 생성/보정
- 제목/본문 웹 편집 및 실시간 길이 표시
- TXT 다운로드, 클립보드 복사
- 한글 한 글자씩 입력, 문장 사이 잠깐 멈춤, 속도 설정
- 입력만/자동 발행, 중지, 입력된 원고 대조
- 발행 직전 로컬 기록, 결과 미확인/완료 원고의 중복 발행 방지

글 작성 모델은 기본 `gpt-4.1-mini`이며 사용 가능한 모델로 변경할 수 있습니다. 실시간 웹 검색 기능은 없습니다. 최신 정보와 개인 경험은 참고 내용에 확인된 사실로 입력하세요. 예시 원고는 UI 확인용이며 발행할 수 없습니다.

## 데이터 처리

- **API 키:** 웹 탭의 메모리에만 보관합니다. 새로고침/종료 시 지워집니다. `api.openai.com`으로만 전송합니다. 키를 저장소에 커밋하거나 사이트 공통 키로 넣지 마세요.
- **생성 데이터:** 키워드와 참고 내용은 사용자의 OpenAI API 요청으로 전송됩니다. `store:false`를 사용합니다. OpenAI의 API 데이터 정책은 별도로 적용됩니다.
- **웹 설정:** 블로그 ID, 모델, 속도만 브라우저 localStorage에 저장합니다.
- **연결 확장:** 웹앱의 정확한 도메인/경로와 네이버 블로그만 연결합니다. API 키를 받지 않습니다. 발행 이력의 해시·블로그 ID·제목·상태·URL은 확장 로컬 저장소에 남고, 현재 작업 원고는 브라우저 세션 저장소에 남습니다.
- GitHub 저장소에는 프로그램 코드와 안내만 올라갑니다. 사용자의 생성 원고와 API 키를 GitHub에 업로드하지 않습니다.

## 입력/발행 주의점과 검증 범위

네이버 편집기는 **빈 글쓰기 화면**으로 준비해 주세요. 로그인/보안 인증/도움말/임시저장 안내는 직접 처리합니다. 입력 중 해당 네이버 탭을 앞에 두고 편집기를 클릭하지 마세요. 기존 글은 덮어쓰지 않으며, 입력하려는 원고와 정확히 같은 글이면 재입력을 생략할 수 있습니다.

소제목은 번호와 줄바꿈으로 입력합니다. 이미지, 네이버 인용구 디자인, 예약 발행, 카테고리/공개 범위 변경은 포함하지 않습니다. **현재 네이버 발행 설정을 사용합니다.** 첫 사용에서 ‘입력만’으로 설정을 확인할 수 있습니다.

최종 발행 요청 이후 중지하거나 연결이 끊기면 실제 글이 게시되었을 수 있습니다. 결과가 불확실하면 자동으로 재시도하지 않습니다. 블로그를 직접 확인하세요. 확장 프로그램을 제거하면 로컬 중복 방지 이력도 사라집니다.

로컬 자동 테스트와 웹 화면, 모의 편집기 입력 흐름을 검증합니다. **실제 API 키로의 생성과 로그인한 네이버 계정의 최종 발행은 미검증**입니다. 네이버 DOM 변경 시 `extension/naver.js`의 선택자나 입력 방식을 업데이트해야 할 수 있습니다. 이 프로젝트는 네이버 공식 서비스가 아닙니다.

## 개발

Node.js 22 이상, 확장 ZIP 패키징에는 Python 3이 필요합니다. 런타임 npm 의존성은 없습니다.

```sh
npm test
python scripts/package-extension.py
npm run serve
```

로컬 웹 주소: `http://127.0.0.1:4173` (웹 UI 테스트용). 확장 연결은 공개된 GitHub Pages 주소에만 허용됩니다. 로컬 테스트를 위해 일반 웹사이트 접근 권한을 넓히지 않았습니다.

## GitHub Pages 배포

저장소 Settings → Pages에서 `main` 브랜치의 `/docs`를 선택합니다. `docs`에는 정적 웹앱과 연결 확장 ZIP이 들어 있습니다. 변경 후 테스트와 확장 패키징을 다시 수행하고 커밋하면 Pages가 갱신됩니다. `extension/core.js`는 `docs/core.js`의 생성된 복사본입니다.

다른 계정으로 포크하면 `extension/manifest.json`, `bridge.js`, `policy.js`, `background.js`의 허용 웹 주소를 해당 계정의 실제 Pages 주소로 수정하고 확장을 다시 패키징해야 합니다.
